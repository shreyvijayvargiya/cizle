# What's new

**Goal:** keep users and followers in the loop and show momentum. Works as a build-in-public post, a release announcement and a customer update.

## Structure and motion
1. **Headline (2-3 s)** `title`: "What's new in <product>" with the date or version as the subtitle.
2. **The changes (3-4 s each, 3 of them)** `bullets` or `screenshot`: one shipped change per scene, written as the benefit ("Export to CSV, one click"). The newest or most visible change goes first.
3. **Small stuff (3 s, optional)** `bullets`: "Also: dark mode, 12 fixes".
4. **Momentum (2-3 s, optional)** `stats`: only numbers the sources give (releases this month, contributors).
5. **Outro (3 s)** `outro`: "Update now" or "Read the changelog" and the URL.

## In each style
- **Clean:** a release-notes card per change, screenshot where there is UI.
- **Clay:** each change is a gift-box card that pops open.
- **Glass:** changelog entries as frosted notifications sliding in.
- **Isometric:** new blocks drop onto the stack one by one.
- **Hand-drawn:** a checklist ticking off, each item drawn in.
- **ASCII:** a literal changelog: `+ added`, `~ improved`, `- removed`.

## Rules
- Use merged pull requests, releases and the product's change notes only. Never announce something that is only planned or only in a branch.
- Write the benefit in user language: not "refactored the exporter", but "Exports are 3x faster" only if a source says 3x.
- Three headline changes at most. The rest is "Also: ...".
