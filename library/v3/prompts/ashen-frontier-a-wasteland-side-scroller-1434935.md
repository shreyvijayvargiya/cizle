# ASHEN FRONTIER: a wasteland side-scroller

By @jiangjiangling · Opus 5.5 · 像素与角色
Language: ? · Domains: general · Source: V01

Original post: https://x.com/jiangjiangling/status/2107399895011434935

```
用 Codex 做了一款末世横版动作游戏。

死林营地 → 废弃街区 → 机械工厂 → 双阶段 Boss。
跑跳、翻滚、近战三连、霰弹破甲，配上游戏原声。

这 30 秒是一次生成的实机录制，不是 AI 生成的视频。

技术栈：原生 JavaScript + Canvas 2D。

提示词如下：
你是一支具备游戏策划、2D美术、角色动画、战斗设计、音频和前端开发能力的独立游戏团队。请直接制作一款完整、可玩、有明确美术风格的横版动作游戏《灰烬边境 / ASHEN FRONTIER》，完成后交付游戏源码、可玩入口和30秒带原声的实机宣传片。

这不是功能演示，也不是用静态立绘平移拼成的概念稿。我要的效果是：阴暗但清楚的战场、连贯的角色动作、有力度的近战和射击、不断变化的关卡空间，以及具有两种形态的机械Boss。请将以下要求落实到实际运行画面和玩法中。

一、工作方式

先检查当前工作区。如果已有项目，沿用并改善现有实现，保留可玩的回退版本；如果没有项目，再创建新项目。

先完成可玩的核心闭环，再将同一套美术、动作、光照和反馈贯穿全部关卡。不要只精修首页，进入游戏后却退回占位图形。

如果提供了参考视频，必须实际读取视频，并按开场、跑步、跳跃、三段近战、射击、场景过渡、Boss变身等关键片段连续采样。记录构图、角色比例、动作节奏和反馈差距。不能只看封面猜玩法，也不能没读取视频就声称已经逐帧对照。

采用原创角色、场景和音频，学习参考作品的机制、表现层次与完成度。

常规实现选择由你直接决定；遇到问题先定位、修复和复测。持续提供简短进展，但不要每完成一小项就结束交付，也不要把视觉验收全部推给我。

二、技术和运行目标

使用原生JavaScript ES模块、HTML5 Canvas 2D和Web Audio实现。

游戏应能在浏览器直接运行，支持本地开发和静态构建。字体、图片、音效等运行资源尽量本地打包，游戏过程中不依赖实时调用生成服务。

把模拟、输入、渲染、角色动作、场景、战斗、特效、音频和UI分开组织。战斗与碰撞采用固定模拟步长，渲染插值，避免刷新率改变移动速度、攻击次数或伤害。

以1280×720、16:9横屏作为主要构图，适配窗口缩放。手机横屏提供触控按键；竖屏给出简洁的旋转提示。触控按钮不能遮住角色和主要交战区域。

正常游玩目标为稳定60fps，但必须报告实际测量结果。避免每帧生成纹理、大面积模糊、重复创建音源或无限累积粒子。

三、故事与整体气质

主角是一名穿旧皮衣的边境巡林者。战争机器吞没了最后的居民区，他必须穿过死林、无人街区和旧兵工厂，击败守门机器，重新打开通往外界的道路。

故事通过开场短文、场景名称、环境物件和关卡推进表达，不用频繁弹窗打断战斗。

整体采用阴暗、克制、带工业废土气息的精细2D手绘风格：
- 环境：灰绿、烟灰、褐色和低饱和冷青。
- 主角：暖棕皮衣、深色长裤、清晰的头部和肩部轮廓。
- 光源：暖橙火焰、冷青工业灯和少量危险红光。
- 金属：磨损、锈蚀和接缝清楚，但不过度堆积碎纹。
- 战斗：枪口、弹丸核心和命中点比背景更亮，形成局部视觉焦点。

不要把“阴暗”做成整屏发黑，也不要靠全屏白光制造打击感。

四、场景和关卡

制作一条可以连续走通的横向路线，包含四个区域：

1. 死林营地
前景为不规则枯枝和树干，中景为帐篷、火桶、木箱、长椅和巡林者，远景为被雾遮住的死树林。
开场应有空间层次、空气透视、火焰动画和少量飘落颗粒。
前景枝干经过角色附近时适度淡化，不能长期遮挡操作。
营地之后安排首批地面机械兵和飞行敌人，用来展示跑步、三段近战和霰弹射击。

2. 无人街区
加入破损店面、工业招牌、路灯、路障、残骸和冷色灯管。
形成开阔交火区与短距离掩体区的变化，不是一条空地换一张背景。
敌人位置应推动玩家移动、翻滚或跳跃，避免全部站在同一高度等待射击。

3. 旧兵工厂
使用有厚度的金属平台、支柱、楼梯或设备结构，形成上下层路线。
平台必须与其实体结构对应，不能出现悬浮细线或无法理解的碰撞面。
安排跳上平台、空中射击、从单向平台落下和跨越障碍的组合。
角色脚底、投影和平台接触关系必须准确。

4. 边境守门人
战斗场地有足够横向躲避空间，边界清楚。
背景包含废弃厂房、铁门或机械残骸，保持危险标记的可读性。
Boss体型明显大于普通敌人，但镜头应同时看清玩家、Boss和主要攻击预警。

四个区域需要通过背景层叠、雾色、建筑密度和光照渐变连接。不能跨过某个坐标就突然整张背景切换。

设置合理的补给和检查点，失败后允许从检查点继续。

五、主角动作系统

角色必须有真正可读的动作变化。可以使用逐帧精灵，也可以使用经过正确分层的2D骨架，但不能只让整张立绘左右摇晃。

至少完成：
待机、起跑、持续奔跑、停止、转身、起跳、上升、下落、落地、翻滚、射击、装填、三段近战、受击和死亡。

动作要求：
- 跑步有明确的支撑腿、摆动腿和短暂腾空，脚步频率与移动速度匹配。
- 停止时有短收势，但不能拖延操作响应。
- 肩、胯、手臂和武器之间有自然的联动。
- 枪托、握把、扳机手和支撑手保持接触，不能穿过躯干或悬在空中。
- 翻转朝向后，前后手和腿的遮挡关系仍然正确。
- 不能通过拉长骨骼或扭曲整个人物去够到攻击目标。
- 跳跃和落地有重心变化，角色不能像纸片上下平移。
- 翻滚有紧凑姿态、短暂残影和落地扬尘，结束后立即恢复可控状态。
- 衣摆和随身物件有轻微延迟，但不能乱甩或与双腿反复穿插。

将站立、奔跑、跳跃和攻击之间的衔接作为完整动作链检查，而不是分别截一张好看的姿态就认为完成。

六、输入与基本战斗

键盘：
A/D或方向键移动；
Space跳跃；
J近战，连续输入可接三段；
按住K连续发射霰弹；
Shift或L翻滚；
R装填；
S+Space从单向平台落下；
Esc或P暂停；
M静音；
H显示或隐藏操作说明。

移动要即时、稳定，跳跃高度和空中控制容易理解。松开方向后不能持续滑行很远。

角色、敌人和Boss均受实体地形约束。翻滚不能把人物塞进石块或墙体，落地后不能卡住。受击击退也需要通过碰撞处理。

七、三段近战

三段必须在姿态、刀路、节奏和声音上可区分：
第一段快速切入；
第二段反向接续；
第三段短暂蓄势后重斩，带更明显的身体重心变化。

可采用以下初始参数，并通过实战校准：
- 第一段总时长约0.32秒，基础伤害25。
- 第二段总时长约0.30秒，基础伤害32。
- 第三段总时长约0.54秒，基础伤害46。
- 支持短时间输入缓存，提前连按能接续，不能每次按键都重置第一段。
- 按住J不应无条件重复触发整套连击。
- 攻击恢复、翻滚取消和受击打断的规则必须一致。

近战必须有足够舒适的触及距离，不能要求人物几乎贴进敌人身体才能命中。
前两段能清楚扫到身前敌人，第三段更远、更宽。

刀光和命中区域由同一组挥砍轨迹驱动：
可在实体刀尖之外形成40、48、60个世界单位左右的刀光延展，并根据角色比例调整。
不要把手臂或刀身放大来伪造范围。
不能出现刀光扫到却没伤害，或者完全没有刀光的区域凭空受伤。

保留朝向限制与墙体遮挡；同一个敌人在同一段攻击中只结算一次伤害。
允许一刀命中多个处于有效范围内的敌人。

八、射击与打击反馈

使用扇形霰弹，近距离更容易集中命中。
弹仓容量、射击间隔、装填耗时和伤害关系需平衡，不能无限无间隔连发。

一次射击应包含：
压枪准备或即时扳机响应；
枪口闪光；
肩部后坐；
发光弹丸核心与短尾迹；
命中火花；
敌人局部闪白或颜色变化；
短暂命中停顿；
方向明确的击退；
死亡与掉落。

把同一发霰弹的主反馈聚合处理，避免每颗弹丸同时堆叠巨大数字和满屏爆炸。

区分：
普通命中、近距离重击、近战终结、击中金属掩体、击杀和Boss装甲破裂。

普通命中反馈短促；
重击有更重的低频、火花与微量震屏；
击杀有清楚的失衡、倒地或机械碎片；
Boss变身才使用更大规模的破裂和灯光变化。

光效采用亮核心、暖色外沿、短寿命尾迹和局部环境反光，避免所有东西都变成同样的黄色光球。

九、敌人与Boss

普通敌人至少包括：
- 近战机械兵：接近、蓄势、挥击、恢复和受击。
- 远程机械兵：寻找射线、短预警、点射或连射、换位。
- 飞行无人机：具有轻微上下浮动和可读的发射预警。

敌人不能像贴纸一样恒速平移。地面敌人需要步态；无人机需要推进或悬停反馈；攻击时有独立动作。

不要让所有敌人全地图追踪。接敌、开火与追击必须有合理范围，并受地形影响。

Boss“铁脊”至少具备：

第一阶段：装甲形态
- 重量明确的行走；
- 炮口瞄准与连射；
- 有预备动作的冲撞；
- 抬臂后砸地；
- 攻击后的可反击空档。

第二阶段：核心过载
在约半血时真实触发变身。
包含装甲开裂、碎片掉落、躯干展开或姿态改变、核心亮起、短暂变身保护和阶段提示。
不能只是把贴图染红或让血条恢复。

第二阶段增加或改变：
- 锁定落点后延迟落下的迫击炮；
- 两次有节奏差的连续重击；
- 沿地面扩张的冲击波；
- 更积极的换位，但仍保留恢复窗口。

危险标记必须在命中前出现。
迫击炮落点锁定后不再跟随玩家。
冲击波按移动中的环形或波前边缘判断，不能整个圆盘持续造成伤害。
翻滚无敌、跳跃躲避与受击免疫必须真实有效。

Boss死亡后停止造成伤害，完成明确的死亡表现和通关结算。

十、声音

用统一的音频总线管理音效和BGM。

必须听得到：
脚步、起跳、落地、翻滚；
三种不同层次的挥刀声；
近战命中和重击；
玩家枪声、敌人枪声和金属跳弹；
装填开始、装入弹药、闭锁完成；
受伤、击杀、拾取、检查点；
Boss预警、重击、炮击、变身和死亡；
按钮确认、暂停恢复与通关。

玩家枪声必须足够靠前，不能被BGM掩盖。
BGM保持压抑的环境气氛，进入Boss战后提升节奏与紧张感，二阶段进一步变化。
重大攻击可短暂压低音乐，但不能让所有声音突然消失。

限制同时发声音源数量，释放结束节点，处理浏览器首次交互解锁音频。
暂停时同时暂停游戏声音，恢复后不能重复触发之前的攻击声。

十一、开场、UI与镜头

开场使用真实可玩的营地作为背景，不另放一张与游戏完全不同的宣传画。

主页有清楚的游戏名、简短背景和开始入口。
开始后保持同一场景连续呈现，主页文字淡出，场景名称淡入再淡出。

区域名称居中，采用克制的衬线标题、细线和小号英文副题：
“死林营地 / DEADWOOD CAMP”等。
标题展示不锁住玩家操作。

右上角提供简洁的操作说明，展示一段时间后自动淡出，H可重新查看。
不要把全部操作永久堆在画面底部。

左上角用清晰的生命格、弹药数量和翻滚状态传达战斗信息。
Boss出现时展示名称、血条、阶段及必要预警提示。

统一剧情提示、拾取提示和阶段提示的显示区域与优先级，避免叠字。
镜头平滑跟随，保留前方视野，不在地图边缘把人物挤到UI下方。
跳跃和Boss战中的镜头变化要克制，不能让瞄准和落点判断失控。

十二、性能与质量验收

必须实际进入游戏操作并完成通关，不以直接改坐标、改血或设置胜利标记代替验证。

至少检查：
左右移动及反向；
跑跳、落地和平台穿下；
三段近战的缓存、接续、取消和范围；
同段多目标命中与防止重复伤害；
射击、空弹、装填和掩体阻挡；
敌人移动与攻击；
翻滚无敌；
Boss两阶段、落点锁定和冲击波；
死亡、检查点恢复、暂停及重玩；
音频解锁、音量平衡和音源回收。

对角色检查连续帧，重点看手臂、武器、衣服和双腿是否穿插。
对场景检查碰撞与可见轮廓是否对应。
对战斗检查刀光、枪口、弹丸、受击和声音是否同步。

测试通过不代表美术已经合格。还要实际检查角色轮廓、场景层次、光效力度、动作节奏和UI清晰度，并优先修复最明显的视觉问题。

十三、30秒实机宣传片

使用完成后的最新版本重新录制，不复用旧版本视频。

时长严格30秒，横屏16:9。
内容优先展示：
营地开场与场景标题；
自然跑动和跳跃；
完整三段近战及击杀；
霰弹射击和敌人反馈；
工厂平台战斗；
Boss变身、第二阶段和高潮。

用真实操作推进；允许剪掉赶路与等待，不允许改血、传送、强制刷怪或假造通关。
画面可使用精简HUD和片名，但不能把编辑添加的内容伪装成游戏已有功能。

必须录入游戏原声和BGM，不能交付无声录像。
不要把低帧率录制简单转码成60fps后声称流畅。
优先稳定的真实帧率，检查连续动作、重复帧、长停帧、音画同步和切点。

交付H.264/AAC的MP4文件，核对实际时长、尺寸、帧数和音轨，完整解码检查后再提供。

最终交付：
1. 可实际打开的游戏入口。
2. 完整源码、运行说明与静态构建。
3. 30秒带游戏原声的实机MP4。
4. 简短列出已验证的内容和仍存在的具体问题。
不要用“已经达到精品”“高度还原”替代证据，让实际运行画面证明完成度。
```
