# プロダクトデモ動画 ハウススタイル・テンプレート（汎用）

> 高クラフトな「キネティック・プロダクトデモ動画」を、**どのサービス／プロダクトでも再現性高く**量産するための創作ディレクション。
> **技法（craft）は普遍、皮（ブランド）は差し替え**。#1の記入ブリーフを埋め、§4の精査で実プロダクトのデザインを取り込めば、同じ品質・同じモーション言語・同じ構成が別プロダクトで再生産できる。
> **このファイル単体で完結**：ヒアリング → 精査 → 絵コンテ → 実装 → 検品 → レンダリング → 配信までを内包（外部ドキュメント不要）。

> ⚙️ **実行時の最初の挙動（重要）**：このスキルが起動したら、いきなり作り始めない。**まず「#1 記入ブリーフ」の項目をユーザーにヒアリングする**。会話の文脈で既に判明している項目は飛ばし、**不足している★印（最低限）が埋まらないうちは絵コンテ・実装に進まない**。質問は `AskUserQuestion` 等で1〜4問に束ねて簡潔に。★が揃ったら§4の精査へ進み、残りの項目は精査結果とドラフトで埋め、要所だけユーザーに確認する。

## 2. 使い方

1. **#1をヒアリング**（★が最優先）。
2. **§4** で実プロダクトを精査する — **コードベース**があれば実コードから、**公開URL**があればライブサイトから、デザインシステム（色・書体・ロゴ・部品・文言）を抽出する。
3. その結果で**§6 ブランドトークン**と#1の残り項目を埋める。
4. **§3 制作哲学**と**§7 モーション設計**は**不変の憲法**。数値・spring値・遷移規約はそのまま使う。
5. **§5 参照解析メソッド**で憧れの動画を分解し、足りない技法を写像（任意・味を上げたいとき）。
6. **§8 構成**のビート・スケルトンを見せる機能に割り付け、**§11** の手順で実装〜配信する。

---

## 3. 制作哲学（不変の原則）

**目指す質感**: 「1画面1要素・巨大・中央・キネティックタイポが"意味"を言い切る・ホイップで繋ぐ・実UIを巨大クロップで見せる」。速いカット、軽い質感、~25〜45秒。

**やらない（アンチパターン）**:
- 全画面の等倍スクショ（文字が小さい・情報過多・単調）
- 帯字幕でストーリーを"説明"する（画が語っていない）
- フェード/スライドだけの均質な遷移（エネルギーがない）
- 冗長な尺
- ロゴ/イラストの手描き近似、ロゴ背後の発光装飾などの"盛り"
- 煽り・誇張・絵文字装飾コピー
- 参照元クリエイターの署名・固有アセット・固有言い回しの模倣（技法だけ借り、表現は自作する）

## 4. 実プロダクト精査 → デザインを"完全に一貫"させる【最重要・最初にやる】

絵コンテを書く前に、対象プロダクトの**実デザインシステムを抽出**し、動画のデザインを実プロダクトと**見分けがつかない**水準（同じトークン・同じ文言・同じ部品・同じロゴ）に揃える。ここを飛ばすと"それっぽいが別物"になる。ソースは2系統、**両方あれば両方使って突き合わせる**。

### (A) コードベース精査（リポジトリがある場合）
読み取り専用のサブエージェント（Explore等）に **very thorough** で投げ、**file:line の一次情報**で回収する。
1. **デザイントークン抽出**: `tailwind.config.*` / theme / CSS変数 / `docs/*design*` から**色hex・余白・角丸・影・書体・グラデ**を実値で採取。
2. **UI文言の逐語転記**: 見せる画面のラベル/ボタン/プレースホルダを`locale`分岐から**言語ごとに一字一句・file:line付き**で回収。想像で書かない。
3. **コンポーネント見た目の写経**: 見せるUI部品（カード/ピル/タブ/トグル/チャット/ローディング等）のクラス・比率・状態（active/hover/disabled）をそのまま写す。**巨大化しても比率とトークンは実物のまま**。
4. **実ブランドアセットの特定**: `public/` 等のロゴ・象徴イラスト・背景画像を使う。

### (B) 公開サイト精査（ライブの実プロダクトURLがある場合｜色・ロゴは実物から取る）
ブラウザ自動化（例: Claude-in-Chrome の `navigate`/`read_page`/`javascript_tool`/`computer`）または WebFetch で、**実際にレンダリングされた見た目**から採取する。ビルド後の実値＝ユーザーが本当に見ている色・ロゴなので、ここを正とする。
1. **カラー（実物）**: `getComputedStyle(document.documentElement)` でCSSカスタムプロパティ（`--color-*`等）を吸い出す＋主要UI要素の`color`/`background`/`border`/グラデを**計算値**で取得。さらにスクショを撮り、キーカラーをピクセルでスポイトして裏取り。→ `{{INK}}`/`{{ACCENT_GRADIENT}}`/`{{PRIMARY}}`/`{{PAPER}}`。
2. **書体（実物）**: 実際に効いている`font-family`/`font-weight`を計算値で確認（webフォント名・ウェイトまで）。→ `{{DISPLAY_FONT}}`。
3. **ロゴ（実物）**: ヘッダーの`<img>`/インライン`<svg>`ロゴ、`link[rel~=icon]`、`meta[property=og:image]` を特定し、**URLから実ファイルをダウンロード**（明/暗両方あれば両方、SVGはそのまま、ラスタは高解像度で）。→ `{{LOGO}}`。手描き近似は禁止、必ず実ロゴを使う。
4. **象徴アセット/背景（実物）**: ヒーローや特徴セクションの実画像・背景（グラデ画像/イラスト/動画）を取得。→ `{{BRAND_IMG}}`。
5. **UI文言（実物）**: 画面に出ている実ラベル/ボタン/プレースホルダを言語切替しつつ採取し、(A)のlocale分岐と突き合わせる。

### 統合・優先・仕上げ
- (A)(B)が食い違ったら **(B)ライブのレンダリング値を優先**（ビルド後の実体）、命名/体系は(A)コードで補完。どちらも無ければブランドガイド/スクショから採取。
- 採取結果を**§6のトークン**と`{{LOGO}}`/`{{BRAND_IMG}}`に埋め、**1枚のdesign-spec SSOT**にまとめて絵コンテ・各シーンの単一情報源にする。
- **一貫性の検算**: 完成フレームを実プロダクト（ライブ画面 or スクショ）と並べ、色・字面・部品・ロゴの食い違いゼロを確認（§10 品質ゲート）。

> **ゴール**: 「動画のこのカード、そのままプロダクトのスクショですよね？」と言われる状態。トークン・文言・部品・ロゴが実装／実サイトと1:1。

## 5. 参照解析メソッド（憧れの動画 → 自プロダクトのハウススタイル）

**手順**: 高品質なプロダクト動画を1本選び、下の6レンズで分解 → 各技法を§6のブランドトークンに写像する。**craftは借り、skinは差し替える**（固有の色・ロゴ・文言・署名は持ち込まない）。

| レンズ | 何を観るか |
|---|---|
| タイポグラフィ | 文字が"主役"か（説明ではないか）、極太/巨大か、1行1語アクセントか、反復や言い換えで価値を語っているか |
| 遷移 | ホイップ（速いパン＋blur）か硬カットか、方向が揃って"1つのカメラ移動"に見えるか |
| カメラ/レイアウト | 1画面1要素か、UIを巨大クロップで見せるか、パンで要素を順に舐めるか |
| カラー/質感 | ブランド1色＋淡い下地の軽い設計か、背景は少数の型に絞られているか |
| ペーシング | 1ビート何秒か、機能ビートとタイポ間奏の交互リズムか |
| UI演出 | 実UIをそのまま巨大に、カーソルで操作、UI内にテキストがストリーム/タイプされるか |

**このテンプレが内包する技法カタログ**（上記メソッドで抽出済みの普遍装置・出典非依存）:

1. **キネティックタイポが価値を語る** — 極太・巨大の1語/1行を高速で切り替え、**1行につきアクセントは1語だけ**。説明文でなく短い断片（問い・命令・対句）で刻む。→ §6 `ACCENT_GRADIENT` を1語に。
2. **反復・言い換えで刺す** — 同義の言葉を型を揃えて連打（多言語反復や対句）。→ **対句のキネティック**（§8）。
3. **ブランドのリボン/ブロブ背景** — ブランド色の大きな波/滲みを斜めに流し、キネティックの下に敷く（大きくblur）。→ §6 背景 type (c)。
4. **ホイップパン＋強いモーションブラー** — 8f前後の横スライド＋blurで抜き、次を逆から入れる。隣接ビートは方向を揃える。→ §7。
5. **UIは巨大クロップ＋最小デバイス枠** — 実UIの1部品を画面幅60〜90%で。ブラウザ/デバイス枠は最小限（信号3つ＋URLバー程度）に。→ §6 UIトークン。
6. **UI内テキストのストリーム/タイプ** — 入力欄にキャレット付きでタイプ、結果カードに回答が流れ込む（アクセント色の語を混ぜる）。→ §7。
7. **巨大カーソルで操作を見せる** — 実ボタンをoversizedカーソルがクリック（リング）。クリック後は必ず消す。→ §7。
8. **軽く明るいパレット＋速いカット** — 白＋ブランド1色、硬カットとホイップの混成、1ビート1〜3.5秒。→ §7/§8。
9. **オープニングは"空の入り口"** — 空の入力欄/検索バーをドンと出し、そこから世界を立ち上げる。→ §8 B1。
10. **借りない物** — 参照元の署名アウトロ・固有ロゴ・固有コピーは持ち込まず、自プロダクトのアセット/文言で作る。

## 6. ブランドトークン（§4の精査結果で埋める変数）

`{{...}}` を対象プロダクトの実値に置換する。右列は**入れ方のヒント**（固有値ではなく形式）。

| 変数 | 用途 | 形式ヒント |
|---|---|---|
| `{{PRODUCT_NAME}}` | ロゴワードマーク/アウトロ | プロダクト名 |
| `{{INK}}` | 見出し/本文の濃色 | near-black（必要なら中間グレーも定義） |
| `{{ACCENT_GRADIENT}}` | キネティック1語＆強調（text-clip） | 3ストップのグラデ（明→中→濃） |
| `{{PRIMARY}}` | ピル枠/スピナー/トグルON | ブランド主色1色 |
| `{{PAPER}}` | 淡い下地 | 主色をごく薄めたペール |
| `{{DISPLAY_FONT}}` | キネティック書体 | 極太(900)のディスプレイ書体 |
| `{{CARD}}` | UIカードの見た目 | 白角丸＋柔らかい影、細いborder |
| `{{PILL}}` | CTA/ピル | rounded-full、accent枠ピル＝border&文字`{{PRIMARY}}`＋背景`{{PAPER}}` |
| `{{BG_A/B/C}}` | 背景3種 | (a)白 (b)`{{PAPER}}`＋accent薄グリッド紙 (c)accent系パステルを大blurしたリボン/ブロブ |
| `{{LOGO}}` | 実ロゴ（明/暗） | §4(B)で実サイトから取得した実ロゴ |
| `{{BRAND_IMG}}` | 象徴イラスト等の実画像 | 本番の実アセット |
| `{{TAGLINE}}` / `{{URL}}` | アウトロ | 一行タグライン／プロダクトURL |

**不変ルール**: 実アセットを使う（手描き近似禁止）／象徴画像は最初から表示（遅延フェード禁止）／背景は上記3種のみ／UIテキストは1080p換算24px以上（注記16px以上）。

## 7. モーション設計（普遍の数値｜そのまま使う）

- **spring**: 登場（少し弾む）`{ damping: 18, mass: 0.8, stiffness: 160 }` / 静定`{ damping: 200 }`
- **キネティック語**: スケール`1.15→1.0`＋y`+30→0`＋opacity、**語ごとに3–4fずらす**（スタッガ）。`{{ACCENT_GRADIENT}}`は1語だけ。
- **ホイップパン**（シーン内完結）: 末尾~8fで`translateX(-120→-1600px相当)`＋`blur(12→20px)`＋わずかにスケール、opacity落として抜け／次先頭~8fで逆方向から入る。**隣接ビートは方向一致＝1つのカメラ移動**。切りたい所は硬カット。ライブラリのTransitionSeries等に頼らず自前処理。
- **巨大カーソル**: OS風ポインタ~90px、drop-shadow、クリックでリング。**クリック後は必ずフェードアウト**（置き去りは頻出バグ）。1ビート1カーソル。
- **タイプライター**: キャレット付き、`cps`で打つ。打ち終わりに`{{ACCENT}}`下線を左→右にスイープ。多言語化で文字数が変わるときは「タイプ完了フレームを固定するcps」を注入し後続のフレーム整合を保つ。
- **UIワイヤー描画**: accentドットが線を引いてUIの器を`stroke-dashoffset`で組み上げ→ラベルがスタンプイン。
- **ローディングもブランドの見せ場**: ロゴピル＋進捗ラベル＋読み取りビーム＋チェック点灯。ただのスピナーにしない。
- **決定性（必須）**: `Math.random`/`Date.now`/引数なし`new Date`禁止。ランダム感はindexで振る。

## 8. 動画構成（普遍テンプレ）

**リズム**: 1ビート=1メッセージ=**2〜3.5秒**、30fps、全体25〜45秒。「**機能ビート → キネティック対句の間奏**」を交互に刻む。実UIを巨大クロップで見せた直後に、極太キネティック1行で意味を言い切る。

**キネティックは対句で**（型を揃えると効く。`{{ACCENT}}`は1語だけ）:
- 「〈行動X〉は、〈手段Y〉と。」の型で並べる／命令・問い・成果でも可
- 多言語版は各言語の約物に合わせる（英語は`、。`でなく`, .`、括弧は`" "`）。対句は維持。

**ビート・スケルトン（差し替え可能なスロット）**:

| # | 役割 | 中身（機能に合わせて割付） | 遷移 |
|---|---|---|---|
| B1 | hook | 空の入力欄/検索バーを巨大に→キャレットで`{{核となる一文}}`を高速タイプ→巨大カーソルが送信 | ホイップ |
| B2 | pain | キネティック対句で課題提起（`{{ACCENT}}`1語） | 硬カット |
| B3 | structuring | ローディングをブランドの見せ場に（ロゴピル＋進捗＋チェック点灯） | ホイップ |
| B4 | promise | タイプライターで価値の一文（打ち終わりにaccent下線スイープ） | 硬カット |
| B5 | wireframe | accentドットが主要UIの器を線で描く→ラベルをスタンプ | 連続 |
| B6 | core-fill | 器に生成/データが流れ込む。**カメラ2〜3回パン**で主要素を順に巨大クロップ | ホイップ |
| Nx | feature | 実UI（タブ/カード/トグル等）を巨大に→カーソルで操作→キネティック対句1行 | 硬/ホイップ |
| … | （機能の数だけNxを反復） | 機能ビート↔キネティック間奏を交互に | |
| B(last-1) | share/outcome | 成果や共有をワンアクションで（トグルON→リンク→"コピーしました"等） | ホイップ |
| Blast | outro | 実ロゴがスプリングイン＋`{{TAGLINE}}`＋`{{URL}}`ピル、最終フレーム静止 | — |

尺を削る/伸ばすときは**1ビート=1メッセージ単位**で機能ビートを増減し、途中フレームの整合を崩さない。

## 9. コピー規範（普遍）

- **事実ベースのみ**。誇張・煽り・絵文字装飾を入れない。
- **実UI忠実**: タブ名/ボタン名/ラベル/プレースホルダは§4で採取した実文字列を**一字一句転記**（多言語はその言語の実文字列）。想像で書かない。
- 文言はシーンに直書きせず**コンテンツSSOTファイル**に集約。
- 未成熟機能（β/α等）の表記は、指示がなければ実UIどおり。

## 10. 品質ゲート（"味"の番人｜出す前に全て満たす）

- [ ] **実プロダクトと1:1**（色・トークン・文言・部品・ロゴが実装／実サイトと一致、スクショと並べて食い違いゼロ）← §4の検算
- [ ] 1画面1要素・巨大・中央（散らからない）
- [ ] 主要素24px以上/注記16px以上、はみ出し・豆腐・重なりゼロ
- [ ] キネティックは1行1語accent、対句として成立
- [ ] 隣接ビートのホイップ方向が一致＝1カメラ移動
- [ ] カーソルはクリック後フェードアウト（置き去りなし）
- [ ] ロゴ背後の発光/手描き近似/帯字幕/絵文字装飾なし
- [ ] 実アセット使用（ロゴは実サイトから取得したもの）、象徴画像は最初から表示
- [ ] キネティックとUIのクリアランス≥40px（登場アニメの最接近フレームでも）
- [ ] 決定性（Math.random/Date.now不使用）
- [ ] 参照元の署名/固有アセット/固有コピーを持ち込んでいない
- [ ] 既存コンポジションに非回帰（共有部品を触ったらstillハッシュで確認）

## 11. 実装・検品・仕上げ（この手順で完結）

参照実装スタックは Remotion（React/TS）を想定。原則は他ツールにも移植可。

1. **実プロダクト精査**（§4）→ design-spec SSOT を作る（コード＋公開サイト）。
2. **絵コンテ=SSOT**: ビート表（key/尺f/内容/遷移方向）＋文言SSOTを1枚に。実装で数値が動いたら必ず追随。
3. **隔離環境で実装**: メイン作業ツリーを汚さないよう git worktree 等で隔離。依存インストールやビルドスクリプトを隔離側で不用意に走らせない（node_modules を symlink 共有している構成だと purge 事故が起きる）。既存コンポジションを壊さない。共有部品を触るなら影響範囲を先に列挙。
4. **still検品**: `remotion still … --frame=N` で各ビート序/中/終＋全ビート境界±4f を出力 → **必ず縮小してから閲覧**（`sips -Z 800` 等。原寸1920pxを直接読むと巨大リクエストで破綻）。実UIスクショと並べて色・字面・部品・ロゴの一貫性を検算。破綻→修正→再検品のループ。
5. **フルレンダリング → 監督レビュー**: 全体はコンタクトシート（`ffmpeg -i out.mp4 -vf "fps=1,scale=480:-1,tile=4x4" sheet%02d.jpg`）で通し確認、疑わしい所だけ高解像度単体（`ffmpeg -ss T -i out.mp4 -frames:v 1 -vf scale=960:-1 k.jpg`）。尺の真値は `ffprobe -select_streams v:0 -count_frames -show_entries stream=nb_read_frames`（コンテナ表示のdurationは丸め誤差が出る）。
6. **仕上げ・配信**: web圧縮 `ffmpeg -i in.mp4 -c:v libx264 -crf 23 -movflags +faststart -pix_fmt yuv420p -an out.mp4`（1080p ~4MB目安）→ 配信先（`public/` 等）へ配置 → ロケール分岐で多言語出し分け → プレビュー環境のビルド成功と実アセット配信を検証ゲートにしてから本番へ。
