# docu-video-maker

参考の URL と題材から、ドキュメンタリー風の解説動画（3分の PV から20分超の長尺まで）を作る。画面は映画のような上下の黒帯で、下の帯に要約した1行の通常テロップ、山場にだけ演出テロップが出る。絵はカットごとに別の素材を当て、静止画は奥行きをつけて動かす。

このスキルの価値は「全部を自動で作ること」ではなく、**叩き台を先に見せ、作り手と短い質問で前提をそろえてから**、品質を落とさずに最後まで作り切ることにある。最初に長い質問票を出さない。まず参考を読んで案を持ってくる。

## 進め方（この順で進める）

### 0. 道具を確かめる

```bash
python3 <このスキル>/scripts/check_env.py
```

ffmpeg・Python の部品・書体・ElevenLabs の鍵・Higgsfield の CLI があるかと、いまの環境で選べる作り方（声・絵・BGM）が出る。足りないものは出力の案内どおりに直す。鍵の値は画面にも会話にも出さない。

### 1. 参考を分析する

```bash
python3 <このスキル>/scripts/analyze_reference.py <URL> [<URL>...] --out <作業フォルダ>/reference --video
```

チャンネルなら動画一覧と再生数・説明欄・アイコン、動画ならサムネ・チャプター・カットの切り替え間隔・コマの一覧が `reference/` に出る。**サムネとコマの一覧は必ず画像として目で見る**（数字だけで作風は分からない）。読み取る項目と差別化の考え方は [references/reference-analysis.md](references/reference-analysis.md)。

### 2. 叩き台を作って見せる

分析をもとに、次を1画面に収まる量で出す。

- コンセプト（チャンネルなら一言の名前と軸、単発なら動画の切り口）
- 題材の候補3つと推奨1つ（理由つき）
- 構成案（ダイジェスト → 題字 → 章 → まとめ、各章の中身を1行ずつ）。構成の形を3つ比べて選んだ理由も1行
- 手本 1〜2 本と、学ぶ所・取らない所
- 見た目の方針（帯・テロップ・絵の配分・カットの速さ）と、参考から**変える点**

書き方の型は [references/interview.md](references/interview.md) の「叩き台」、手本と構成の選び方は [references/directing.md](references/directing.md)。

### 3. 前提を軽く質問する

叩き台に続けて、決めないと作れないことだけを聞く（4問前後。選択肢に推奨を付け、答えやすくする）。

1. 長さ：3分の PV ／10分前後／20分前後
2. 題材と構成：推奨案でよいか、変えたい章はあるか
3. 使える有料サービスと上限：ElevenLabs（声・BGM・効果音）、Higgsfield（AI 画像・動画）のどれがあるか、Higgsfield のクレジット上限
4. 声：候補を3つほど試し読みして選んでもらう（ElevenLabs が無ければ macOS の読み上げ）

答えに応じた設定値は [references/interview.md](references/interview.md) の対応表にある。テロップや画面の細部は、聞かずに既定の型で作り、見せてから直す。

### 4. 台本を作り、事実を確かめる

```bash
python3 <このスキル>/scripts/new_episode.py <作業フォルダ> <slug>
```

ひな形の `script.json` に台本を書く。形式と長さ別の構成は [references/script-format.md](references/script-format.md)。

- 事実は一次資料か信頼できる二次資料で確かめ、出典を `sources.md` に残す。諸説がある所は「〜とされる」「〜と伝わる」で分ける
- 書き終えたら、別の担当（サブエージェントが使えるならそれ）にファクトチェックと誇張の検出をさせ、指摘を直す
- 通常テロップの要約を `subs.json` に書く（句読点なし・1行30字まで）。演出テロップを出す山場を `"fx": true` で選ぶ（約30秒に1回）
- 演出を台本に書き込む：冒頭3秒の引き、山場1つ、締めと冒頭の響き合い、山場や転機の前の静かな間（`"hush"`）2か所以上、見える動きの効果音、音の受け渡し2か所以上。点検の表は [references/directing.md](references/directing.md)
- 台本を作り手に見せて承認を取る。ここで直すのが一番安い

### 5. 素材をそろえる

- 名画：`scripts/commons_fetch.py` でウィキメディア・コモンズから PD / CC0 だけを取る
- 地図：`scripts/fetch_map_data.py` を一度流し、`scene` に地図を書く
- AI 画像・動画（Higgsfield がある場合）：カットごとに別の素材を当てる「カット表」を作り、足りない分を `new_assets.json` に書いて `scripts/gen_assets.py` で作る。**生成の前に枚数と見込みクレジットを示し、上限の承認を取る**
- 生成した画像は必ず一覧にして全部見る。時代違いの物、現代の場面の時代衣装、生々しい描写、実在の現代人物の顔を探して作り直す

集め方・作り方・落とし穴は [references/assets.md](references/assets.md)。

### 6. 音を作り、書き出す前にプレビューで見せる

```bash
cd <このスキル>/scripts
python3 audio.py tts <回>          # 読み上げ（1文ずつ・同時2本）
python3 timeline.py <回>           # 読み上げの実測から時刻表
python3 audio.py sfx               # 効果音（初回だけ・ElevenLabs がある場合）
python3 audio.py bgm <回> v1       # BGM（ElevenLabs がある場合。作り置きの曲なら script.json の "bgm": {"file": …}）
python3 preview.py <回> --serve    # 数秒でプレビューを作り、http://localhost:8765/preview.html で再生
```

プレビューは動画ファイルを作らず、ブラウザが絵・溶け・テロップ・年号・扉・BGM の下げ方・効果音を時刻表どおりにその場で再生する（15分の回で作るのに約3秒）。テロップと年号は書き出しと同じ画像を使う。違うのは、深度による立体化と画面の粒子だけ（平らな寄り・パンで代わりに見せる）。**カット表や台本の直しは、プレビューで作り手に見せて決める**。書き出しの待ち時間を、直しの往復に入れない。サーバーは Range（途中からの読み出し）に答えるので、章へ飛んでも動画と BGM が合う。

### 6b. 書き出す（プレビューで承認が出てから）

```bash
python3 audio.py mix <回> v1       # 声・BGM・効果音を -14 LUFS に
python3 shots.py <回>              # カットと扉（同時に何本も作る）
python3 assemble.py <回> v1        # つないでテロップ・年号・音を重ね、exports/ へ
```

カット表（`shotlist.json`）を変えたら、変わったカットの `shots/NNNN.mp4` を消してから `shots.py` を流す。音と見た目の決まりは [references/audio.md](references/audio.md) と [references/visuals.md](references/visuals.md)。

### 7. 検査する

```bash
python3 <このスキル>/scripts/qa.py <回> v1
```

音量・音の有無・黒い区間・テロップの句読点・素材の使い回し・文字が読み切れる長さかを機械で確かめ、6秒ごとのコマ一覧・全カットの頭/中/終わりの一覧・動きの速い所の全コマを作る（見る道具 `scripts/look.py`）。**一覧は全部見る**。見るべき点は [references/qa.md](references/qa.md)。直したら書き出し直して、もう一度見る。見ていない所を「確認済み」と言わない。

### 7b. 審査に回す

検査で直すことが無くなったら、作っていない担当（サブエージェント）に 7 観点を 1〜10 点で採点させ、時刻つきの直しを 5〜10 件もらう。直して次の版で書き出し、もう一度審査させる（目標は全観点 8 点以上・致命 0、3 周まで）。頼み方の雛形と回し方は [references/review.md](references/review.md)。点数は作り手への報告に添える。

### 8. 公開用の一式を作る

タイトル案・サムネイル・概要欄（チャプター・出典・AI と合成音声の開示）・固定コメント用のクレジット、チャンネルを新しく作る場合は名前・アイコン・説明欄。型と注意は [references/publish-kit.md](references/publish-kit.md)。外に出す文章はファクトチェックと誇張の検出を通す。**YouTube への登録・投稿はしない**（作り手が手動で行う）。

## 作り手に確認するところ

確認なしで進めてよいのは、手元で作り直せる作業だけ。次は必ず止まって聞く。

- 有料の生成（Higgsfield のクレジット、ElevenLabs の大量の文字数）：見込みを出して上限を決めてもらう。上限を超えそうなら途中で止めて相談する
- 台本の承認（素材を作る前）と、書き出した動画の確認
- 実在の人物の声や顔を使うこと、作り手のファイルの削除や上書き

## 作業フォルダ

作り手が指定しなければ `~/Movies/docu-video-maker/<チャンネルや企画の名前>/` に作る。回ごとに `<slug>/`（`script.json`・`subs.json`・`assets/`・`audio/`・`shots/`・`exports/`）。効果音と地図のデータは `~/.cache/docu-video-maker/` に置き、回をまたいで使い回す。
