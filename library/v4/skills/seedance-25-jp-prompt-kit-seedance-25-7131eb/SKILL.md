# Beloved Dog Seedance 2.5 日本語プロンプトキット

English documentation: [SKILL.en.md](SKILL.en.md)

アイデアを、参照素材の役割が明確で、画面上の出来事を制御しやすい日本語プロンプトへ変換する。形容詞を増やすのではなく、人物の動作、カメラ、光、音、連続条件、終端状態を設計する。

## 作業手順

1. 利用画面、生成モード、尺、比率、参照素材、音声、最後に見せたい状態を確認する。利用画面が不明なら、特定UIに依存しないプロンプトを作り、画面固有の機能は未確認と明記する。
2. 上限、API、地域、料金、モデルIDなど変化し得る事実を扱う場合は [公式情報と根拠](references/sources.md) を読み、必要なら公式ページを再確認する。DreaminaのUIとModelArk APIを同一仕様として扱わない。
3. 文章を書く前に参照素材表を作る。各素材へ主役割、所有者、適用区間を割り当て、混入を避けたい場合は「使う要素」と「使わない要素」を対で書く。複数参照では [参照素材の設計](references/reference-contract.md) を読む。
4. シーンの意図、画面で起きる主要変化、主カメラ運動、光源、音、最後の構図を決める。長尺・複数ショットは、重複しない連続区間へ分ける。
5. 最終プロンプトは自然な日本語で書く。ユーザーの `@Image`、`@Video`、`@Audio` 表記を勝手に変えず、存在しない素材を作らない。出力成功や完全一致を保証しない。
6. [25項目の品質確認](references/quality-checklist.md) を実施する。ローカルにプロンプトファイルがある場合は、補助検査として `python3 scripts/prompt_lint.py <file> --duration <秒>` を実行する。自動検査だけで完了扱いにしない。

## 基本形

必要な項目だけ使用する。短い単一ショットへ長いテンプレートを強制しない。

```text
目的: <視聴者に伝えたい変化・感情>
形式: <モード、尺、比率>
参照素材:
- @Image 1 — 役割: 人物。所有者: Mika。適用: 全区間。同一性、髪、服装を使う。背景と元のポーズは使わない。
- @Video 1 — 役割: 動作。所有者: 犬。適用: 5–10秒。加速と停止だけを使う。人物、場所、カメラは使わない。
演出: <人物の動作 + カメラ + 光 + 音>
時間構成:
[0–5秒] <画面で確認できる出来事>
[5–10秒] <画面で確認できる出来事>
連続条件: <人物、服、持ち物、位置、光、音>
終端状態: <最後の人物位置、動作、構図、音>
除外: <実際に混入しそうな要素だけ>
```

## 判断ルール

- 1区間につき主動作1つ、主カメラ運動1つを基本にする。
- 「シネマティック」「壮大」「美しい」「エモい」を、構図、動作、光、演技、音へ翻訳する。
- 参照上限は目標ではない。役割を説明できない素材は外す。
- 編集では「変更するもの」と「維持するもの」を必ず対にする。
- 台詞ごとに話者を示し、尺内で自然に発話できる量へ減らす。
- 続きを作る場合は、採用した動画の実際の最終フレームを確認する。計画より観測結果を優先する。
- 複数人物では、各人の参照、位置、動作、声、持ち物の所有者を分ける。安定性を優先するときは同時接触を減らす。
- 人物の参照画像がない場合は、存在しないTokenを作らず、外見と衣装を文章で定義する。「参照がない人物は登場禁止」とは扱わない。
- 「無人の駅」など場所参照内の人を除外する指示は、指定した登場人物まで排除しないよう「通行人は登場させない。飼い主だけ10秒以降に登場」と区間付きで書く。
- 動物の同一性では、種類、毛色、模様、耳、口吻、尾、体格、首輪など、画面で識別できる固定項目を選ぶ。
- 「台詞なし」は発話を入れない意味であり、完全無音とは限らない。環境音、足音、鳴き声、音楽の有無を別に決める。
- 正確な字幕、ロゴ、商品コピーは、利用画面に信頼できる専用機能がない限り後編集へ回す。
- `Subject Profile`など独自の整理方法をSeedance公式機能として説明しない。

## 必要な資料だけ読む

- モデル上限、編集、延長、提供面の違い: [確認済み機能](references/capabilities.md)
- 人物・動作・音声・場所・商品・クレイ参照: [参照素材の設計](references/reference-contract.md)
- Cutline Studio由来の27実務パターン: [プロンプトパターン](references/patterns.md)
- 完成前または既存プロンプトのレビュー: [25項目の品質確認](references/quality-checklist.md)
- 人物変形、参照混入、カメラ競合、連続性崩れ: [失敗時の修正](references/troubleshooting.md)
- 上限・API・地域・料金等の事実: [公式情報と根拠](references/sources.md)

## 出力形式

1. そのまま貼れる完成プロンプト
2. 参照素材がある場合は短い役割表
3. 重要な注意点または未確認事項を最大3件
4. 失敗結果の修正では、必要がない限り全文を書き直さず変更部分を示す

説明を長くして完成プロンプトを埋もれさせない。
