# 自然写作·审稿

诊断读者实际会遇到的问题，明确指出哪些地方应保留。只有用户要求改写时才提供完整改写稿。

## 先确定审稿对象

区分单篇质量诊断和原稿／改稿保真对比。记录用户的体裁、读者、文风样本和禁止改动项。引用内容、专名、技术术语和必要格式不因为命中观察词就该改。

完整审稿读 [审稿准则](references/review-rubric.md)。需要程序辅助定位时读 [脚本说明](references/scanner.md)，在本机对已获准读取的材料运行 `scripts/prose_scan.py`。脚本只返回线索，不改文件，也不将文字发送给外部服务。短文或语义问题直接人工审阅即可。

对比深改或论文改稿时，额外检查 [保真边界案例](references/fidelity-cases.md)。论文的研究设计和证据规划需要重做时，可指出具体缺口并使用可用的 research-paper-writing；用户只要求审稿时，不擅自开展研究或重写全文。

## 检查顺序

1. **保真和证据。** 对比数字、单位、限定、否定、指代、引用、完成状态及因果。原稿没给的细节是否被改稿冒充事实？主体和数字相同但对应关系改变也算失真。
2. **主线和推进。** 开头的问题有没有回答？相邻段有没有实际关系？是否同一结论换了词重复讲？
3. **表达。** 空泛评价、翻译腔、同义词轮换、伪权威、模板开场与结尾是否影响信息传达？
4. **节奏和文风。** 句段结构是否反复套用？是否从专业稿滑向聊天、从个人叙述滑向宣传？样文中的有效习惯是否被抹平？

按影响排优先级：实质失真优先于结构问题，结构问题优先于装饰性措辞。一次出现的词或标点不构成问题；给出周围语境和它为何妨碍阅读的理由。

## 给可执行意见

每条重要意见尽量包含：位置或短引文、具体问题、建议动作，以及不会添加新事实的局部示例。材料不足时写清需要补充什么，不用虚构细节填满“修改建议”。

默认报告最值得处理的少数问题并指出值得保留的表达；用户要求全面检查时覆盖全部实质问题，按类合并重复发现，保留定位。文本已经合适时直说，不为证明审稿有用强找毛病。

若用户要求分数，使用 [审稿准则](references/review-rubric.md) 的有依据等级，注明是编辑判断；不换算“AI 率”、作者身份概率或检测通过率。

## 检查自己的建议

建议稿也要接受同样的事实、句式和文风检查。不要把一段套话改成“说白了”“真正重要的是”开头的新套话。给出一次有针对性的修正即可；没有证据时不宣称所有问题都已排除。
