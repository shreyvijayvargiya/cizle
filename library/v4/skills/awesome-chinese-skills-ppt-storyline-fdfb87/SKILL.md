# 咨询级 PPT 故事线

## 核心原则

PPT 的逻辑错误没法用设计补救。先定"一句话结论"，再让每一页都是支撑这个结论的台阶——每页的标题连起来读，应该是一段完整通顺的论证。这是金字塔原理的"标题即结论"标准。

## 执行流程

```
构建进度：
- [ ] 第 1 步：明确三要素
- [ ] 第 2 步：写故事线一句话
- [ ] 第 3 步：搭 SCQA 骨架
- [ ] 第 4 步：逐页展开
- [ ] 第 5 步：标题连读检验
```

### 第 1 步：明确三要素

向用户确认（缺一不可）：
- **听众**：谁、已知道什么、反对你什么（预设阻力点）
- **目的**：听完之后要他做什么决定（批预算？签单？给资源？）
- **素材**：手上有哪些数据、案例、已完成事项（没有的不编）

### 第 2 步：一句话故事线

用这句话填空并让用户确认：「我建议（听众）采取（行动），因为（3 个理由中最强的一个）」这句话是全篇的锚，后面所有页面为主旨服务。

### 第 3 步：SCQA 骨架

- **S 情境**：双方都认可的现状（1 页，建立共识）
- **C 冲突**：正在发生/将要发生的问题（1-2 页，制造紧迫）
- **Q 问题**：由此产生的关键抉择（1 页，引出方案）
- **A 答案**：方案主体（3-6 页，每页一个论据）+ 落地计划（1 页）+ 风险与对策（1 页）+ 明确的行动请求（1 页，写清楚要谁在什么时间做什么）

### 第 4 步：逐页展开

每页输出四行：
```
页码 | 结论式标题（≤15字，必须是观点不是"现状分析"这类名词）
论证要点：2-3 条
建议图表类型：对比柱状图/流程图/表格（说明为什么选它）
所需素材：【用户可提供】或【需补数据：具体要什么】
```

### 第 5 步：标题连读检验

把所有页标题按顺序读一遍：如果构成完整递进的论证段落则通过；出现断链（某页标题之间接不上逻辑）就回第 3 步调整。同时检查：行动请求页是否真的存在（最常丢的一页）。

## 常用变体

述职/周报型：成果（量化）→ 归因（我做了什么）→ 反思（1 条真实不足）→ 下阶段承诺（带数字目标）
路演型：痛点 → 方案 → 为什么是我们 → 市场与数据 → 模式 → 计划 → 融资请求

## 红线

所有数据必须来自用户提供或标注【需补数据】；禁止编造市场规模、增长率、竞品情况。
