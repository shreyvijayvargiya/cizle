# 抖音文案仿写引擎 (douyin-fangxie)

## 核心理念（执行时刻记住）

**仿写的单位不是句子，是"观众心理动线"。** 对标的每一句话都在观众脑子里干一件事：让他停下、让他继续看、让他觉得值、让他关注。要抄的是这条动线。

**一句话方法论：结构与机制同构，内容与表达异质。** 骨架抄满（功能位序列、节拍、开环拓扑、价值排布、指纹参数），皮肤全换（案例/数字/比喻/句子全部来自用户素材）。这也是防抄袭线。

**质量不靠"更用力地模仿"，靠流程：** 拆解产物先落盘 → 强制映射表 → 生成时对标原文物理隔离 → 四道闸句级定点重写。任何一步不许跳。

## 工作目录约定

所有产物存到 `~/ClaudeCode/抖音文案仿写skill/workspace/{YYYYMMDD}_{主题短名}/`，包含：
`duibiao.txt`（对标原文）、`deconstruct.md`（三张卡，含原文）、`deconstruct_gen.md`（脱敏版，供生成用）、`mapping.md`（映射表）、`draft.md`（仿写稿）、`qc_report.md`（验收报告）。风格库存 `~/ClaudeCode/抖音文案仿写skill/style_bank/{博主名}.md`，发布归档存 `workspace/published/{日期}_{主题}.md`。
每次完成后回复里给出完整绝对路径。

## Step -1 选题预检（用户报新闻/热点/商业类选题时执行）

用户自定的选题五判（+1 条定位扣回），逐条给 ✅/⚠️/❌ 和一句理由；≥2 条 ❌ 建议换题或换角度，并给出换角度方案：

1. **10秒讲清主角**：一句话能否让陌生观众知道"谁干了什么"？讲不清 → 换一个人人认识的实体当主角切入。
2. **有冲突**：能否写成一组对立（人vs人／新vs旧／明面vs暗面／嘴上说的vs实际干的）？无冲突 = 无情绪曲线。
3. **普通人关心的后果**：后果能否落到钱包/工作/孩子/健康四件套之一？落不到 = 行业新闻，不是大众内容。
4. **表面新闻→商业逻辑**：有没有一层"大多数人看不到"的商业/机制解读？（本账号差异化位，对应口味库"认知增量"）
5. **点开欲自测**：把标题/首句写出来，是否命中口味库机制排行前二（反常识颠覆/好奇缺口）之一？没命中先重写角度再判生死。
6. **定位扣回（可选但默认查）**：能否自然落回账号定位（AI/企业/提效）？破例可以，但要明示"本条不扣定位"。

## Step 0 输入协议（缺一不开拆）

1. **分流**：用户给 1 条对标 → **A模式·单条复刻**；给 2 条 → 选与用户主题更近的一条为主对标走 A模式，另一条只用于指纹交叉验证与钩子机制参考，不做结构基准；给 ≥3 条（同博主或同赛道）→ **B模式·风格库沉淀**（见文末）。B模式沉淀完，单篇仿写仍须指定一条主对标做结构基准。
   **只给主题不给对标时（C模式）**：从 `style_bank/_用户口味库.md` 末尾的 10 条索引里选结构最匹配的一条做主对标（原文在 `duibiao_library/`，结构卡在拆解汇总里已备好），报给用户确认后走 A模式。
2. **对标必须是逐字稿全文**。用户只给抖音链接时，走 `a-lie-distiller` skill 的下载+本地转写管线拿逐字稿，不接受内容概述。
3. **用户素材表单**（口头收齐即可，不必逼用户填表）：
   - 主题一句话
   - 想让观众带走的一个点（价值承诺）
   - 素材要点 3-8 条，编号 M1-M8（必须是真实的事实/数字/案例/亲历细节）
   - 禁区词与不能说的话
   - 人设一句话
4. **判内容型**（三信号，详见 [references/structure-skeleton.md](references/structure-skeleton.md)）：有无价值承诺句；中段信息块可否换序；收束是清单回收还是金句升华。→ 干货型 / 观点型 / 混合型（按主骨架标）。**本用户默认观点型为主**。类型与用户素材错配时（如观点型对标 × 教程类素材）先预警：换对标，或把素材换角度改写成匹配类型。
5. **素材不够填满对标功能位时，停下来向用户要，禁止编造事实。**

## Step 1 拆解：三张卡落盘（deconstruct.md）

> 不落盘的拆解会被模型的"平均文风"引力拉回平庸。三张卡是后续映射、生成、自检的唯一依据（single source of truth）。拆完先展示给用户核对——拆错了后面全错。

**① 结构卡**——逐句一行：

| 句序 | 原句 | 功能位 | 心理机制 | 字数 | 新信息(I/H/E/F) |

- 功能位从 [references/structure-skeleton.md](references/structure-skeleton.md) 的受控词表选（观点型：立场钩S/场景共鸣M/树靶子A/递进施压E/反转揭示RV/共情抚慰W/金句G/身份召集C；干货型：钩子H/圈人R/承诺P/资格证明Q/干货块V/再钩RH/转折T/金句G/引导C）。禁止自造模糊标签（"引入""过渡"）——出现这类标签说明没拆出机制，重拆。
- 心理机制从 [references/stay-mechanisms.md](references/stay-mechanisms.md) 的 19 种机制选标签。
- I=新信息事件 / H=钩子拍 / E=展开 / F=填充口水句。

**② 节拍参数表**（结构卡下方汇总）：
- 语速 = 净字数÷时长（无时长信息按 4.5-5.5 字/秒估）；总字数预算
- 平均 I 间隔、最长无 I 空窗（换算成秒）
- 开环-闭环拓扑：每个坑的开坑句/坑型/挂起时长/闭合方式，标出嵌套环与外溢环（绑CTA不填的坑）
- 转折点：位置百分比 + 方向 + 落差幅度（逐句情绪打分 -2~+2）
- 价值排布矩阵：每个价值点的 重量(核心/次核/佐证) × 位置% × 完整度(全给/半给/零给)
- 各功能块字数占比

**③ 风格卡**——按 [references/style-fingerprint.md](references/style-fingerprint.md) 提取，S级必填带数字区间：平均句长与长短句节奏型、口头禅与标志性词块、人称与称呼系统、句类配比与反问密度、连接词习惯；A级尽量填：语气词系统、金句句式模板、开场指纹。
**单条纯文字输入的降级规则**：口头禅 = 单条内出现 ≥2 次的 2-4 字词块；换气节奏 = 按标点+语义近似断句估算；无时长信息时语速取 4.5-5.5 字/秒中值。所有估算值加 `~` 前缀，指纹闸对带 `~` 的维度只查方向、不卡 ±15%。禁止为填卡编造伪精确数字。

**④ 机制标注两问**（必须明确指认）：观众在第几句决定不划走、靠什么机制？价值在第几句兑现、兑现物是什么？

## Step 2 映射：素材→功能位（mapping.md，未过审不许动笔）

每行 = 结构卡的一个功能位：

| 功能位 | 原文实现机制摘要 | 素材候选(M编号) | 采用方案一句话 | 缺口标记 |

三条硬规则：
1. "机制摘要"只写机制（如"用具体到个位数的金额制造反差"），**禁止出现原文连续 5 字以上字符串**。
2. 每个功能位必须有 ≥1 个 M 编号支撑，或明确标"缺口"。
3. 缺口处理三选一，经用户确认：补料（问用户要）/ 换机制（同功能位换手法，功能位不可删、观点型序列不可乱）/ 删位。

钩子位特殊对待：给 2-3 个候选写法，标注各自机制强度，选最强或交用户选。候选排序依据：有发布数据回流时用实测权重；没有时用 `style_bank/_用户口味库.md` 的停留机制排行做先验（用户口味：反常识颠覆 > 好奇缺口 > 权威借势 > 利益前置 > 点名）。

## Step 3 生成：窄通道（draft.md）

**先做脱敏**：从 deconstruct.md 派生 `deconstruct_gen.md`——删除结构卡的"原句"列（保留句序/功能位/心理机制/字数/IHEF）、删除机制标注两问的"原文证据"、开环拓扑只留坑型与参数不留开坑句原文。结构卡逐句带原文，直接给生成子代理等于把对标全文送进上下文，隔离就失效了。

**上下文纪律（本 skill 最关键的一条）：写正文必须通过 Agent 子代理执行，子代理的 prompt 只允许包含——脱敏版拆解卡（deconstruct_gen.md）、风格卡、映射表、用户素材、双清单。严禁出现对标原文的任何句子。** 模型只能通过机制化的窄通道接触对标，照抄在物理上不可能。

子代理 prompt 附带双清单：
- **必须复刻**：功能位顺序与数量、每位的钩子机制类型、句长节奏型、再钩间隔、承诺-兑现结构、转折位置与落差、人称口吻、连接词类型、各块字数配额（预算±10%）。
- **禁止复制**：与原文任何连续 ≥7 字重合（专有名词除外）、原文的案例/数字/比喻本体、金句换名词式模板填空。

按拍生成：钩子先出 2-3 版定 1 版，再逐段推进；情绪峰顶必须落短句。写超时按优先级砍：先 F、再 E，绝不砍 I/H/转折句。

生成后三道机检：
1. `python3 ~/.claude/skills/douyin-fangxie/scripts/overlap_check.py <workspace>/duibiao.txt <workspace>/draft.md` —— 7-gram 查重，报告重合片段。
2. 对 draft 逐句反标功能位，与结构卡做 diff：缺失/错序/被合并的功能位逐一列出。
3. 数字与专名溯源：列出 draft 中全部数字/专有名词/案例，逐个标注来源 M 编号；无源者删除或停下问用户补料。虚构精确数字被拆穿是账号级信任崩塌，价值闸要求"兑现句具体"不构成编数字的理由。

## Step 4 四道闸自检（qc_report.md，顺序不可换）

每闸输出「句号 + 失败原因 + 该句功能位 + 重写指令」；**定点重写只动命中句及前后各一句**，重写后只复跑失败闸 + 结构diff；整篇重写仅当结构 diff 失败超 40% 时允许。
**返修同样走窄通道**：句级 patch 也通过 Agent 子代理执行，patch prompt 只含失败句及前后各一句、该句功能位与机制标签、风格卡相关参数、重写指令。主上下文（已读过对标原文）禁止直接改写正文——返修恰恰是最容易顺手滑向原句的时刻。

1. **停留闸**：前 15 字是否触发与结构卡同类的停留机制；逐句问"读到这我为什么不划走"，标出第一个可划走点；最长无 I 空窗 ≤ 对标。
2. **价值闸**：开头承诺是否在正文兑现；兑现句是否具体（数字/步骤/案例，而非"真的很有用"式空话）；让不了解背景的人复述，带走点数量与对标相当。
3. **指纹闸**：风格卡逐项比对（节奏型/口头禅类型/人称/称呼/反问密度），偏差 >±15% 列为不符项。
4. **AI味闸**：挂本机 `dbs-ai-check` 的 22 特征清单逐条定位（短视频文稿体裁：段段金句豁免、开头三件套加严）；修复时按风格卡的语言DNA改，不按通用书面语改。

终审一句话判据：读起来像**"同一个人换了个话题在讲"**，而不是"同一篇文章换了批名词"。

## Step 5 交付

仿写稿 + 预计口播时长（字数÷对标语速）+ qc_report 摘要（达标项打钩、遗留风险）+ 工作目录绝对路径。提示用户：**念一遍**——所有指纹维度以听感为最终裁判。

## B模式：风格库沉淀（≥3条对标）

每条各拆一份三张卡（可并行 Agent 子代理执行），然后汇总 `style_bank/{博主名}.md`：
- 共性结构：高频功能位序列及变体、节拍参数区间
- 共性指纹：S/A级维度的稳定值
- 钩子机制分布：TA 最常用哪几种停留机制、各自出现在什么选题上
- 注明：沉淀的是共性，**单篇仿写仍需指定一条主对标做结构基准**（共性归纳会抹掉单条爆款的具体停留机制）。

## 数据回流（可选，用户说"复盘"时执行）

1. **归档**：每篇成稿存 `workspace/published/{日期}_{主题}.md`，记录：所用对标、钩子机制类型、结构指纹摘要、四闸得分。
2. **回填**：发布 3 天后收 5 个字段：5秒完播 / 完播率 / 赞藏比 / 典型评论1-3条 / 涨粉。
3. **更新权重**：按钩子机制标签聚合（n≥3 才更新，加权移动平均），写回 style_bank，行格式：`机制标签 | 指标均值 | 样本数n | 趋势↑↓`。A模式（无博主风格库）写入 `style_bank/_默认.md`。评论区高频词追加进"观众语言库"，下次钩子和兑现句优先用观众自己的词。连续跑输的机制标签降权并提示换对标。
4. **选型联动（闭环的那根线）**：回流数据存在时，Step 2 映射表的钩子位候选排序**必须引用实测权重**，不许拍脑袋。
