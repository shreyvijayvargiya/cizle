# 法言法语 refine-legal-chinese

## 工作边界

- 只处理表达、结构和一致性。不得替用户选择法律规范、诉讼策略、实体结论或证明标准。
- 以中国大陆现行法律语境为基础；港澳台及其他法域慎用。
- 不提供法律意见，不替代现行法研究、事实核查或专业判断。

## 始终执行的安全规则

读取 `references/universal-guardrails.md`，并始终做到：

- 不新增事实、主体、证据、时间、条件、因果、请求或法律结论。
- 不把主张、证据内容或推论升级为有权认定。
- 不改变不确定性、规范强度、否定范围、责任边界或法律效果。
- 不以“完整结构”为由填补材料和法律判断缺口。
- 对旧教材中的法条、期限、样式、历史或域外规则启动现行性和法域闸门。

## 按七个状态工作

### 状态 1：检查输入

先判断进入哪一种入口：

- **直接入口**：用户已提供材料且任务明确时，直接处理，不追加启动问卷。
- **引导入口**：用户第一次使用、不确定如何选择、只描述了模糊目标或明确要求“先问我问题”时，读取 `references/guided-start.md`，通过简短问答帮助其确定处理方式。
- **材料入口**：用户尚未提供待处理文本时，请其粘贴或上传材料，并提示按需脱敏；若目标也不明确，同时使用引导入口。

结构诊断至少需要一份文本，文书链核对至少需要两份关联文本。

### 状态 2：生成内部路由卡

读取 `references/task-router.md`，在内部识别：

1. **工作产品**：记录、请求、回应、分析建议、约定、决定或解释传播；
2. **沟通关系**：谁以什么身份写给谁；
3. **处理动作**：轻度润色、专业改写、严格审校、通俗转译、结构诊断或文书链核对；
4. **修正项**：对抗性、面向有权机关、口头表达、多法域、敏感信息、现行规范或多文书。

按文本的主要功能选择一个主工作产品；确有复合功能时最多再选一个辅助工作产品。不要按部门法或文件名称机械分类。

除非用户要求，不展示完整路由卡。需要说明时只用一行：

`处理建议：回应型 × 律师向法院 × 严格审校。`

### 状态 3：判断是否需要确认

在引导入口中，按 `references/guided-start.md` 最多提出三个短问题；能从用户表述推断的项目不再重复询问。取得足够信息后，用一行确认处理方式，再开始处理或请用户提供材料。

在直接入口中，只有出现下列高影响歧义时，提出最多两个问题并暂停：

- 关键行为主体、写作主体或目标受体不明；
- 日期、金额、请求或事实相互冲突；
- 两种写法会改变法律效果或程序立场；
- 无法判断某种开放性是有意安排还是表达错误；
- 用户要求将未经确认的事实或主张写成确定结论。

能够采用保守表达继续处理时，不为次要偏好暂停。

### 状态 4：按需加载参考

始终读取一个主工作产品文件；复合文本最多增加一个辅助文件：

| 工作产品 | 读取文件 |
|---|---|
| 记录事实、访谈、笔录、时间线、摘要 | `references/function-record.md` |
| 提出诉求、申请、催告或要求行动 | `references/function-request.md` |
| 回应请求、指控、裁判、问询或异议 | `references/function-response.md` |
| 分析问题、形成意见、评估风险 | `references/function-analysis.md` |
| 形成、调整或终止权利义务 | `references/function-agreement.md` |
| 以有权或受托角色形成处理结果 | `references/function-decision.md` |
| 向客户、业务或公众解释法律问题 | `references/function-explanation.md` |

按需增加：

- 用户需要使用前问答引导时读取 `references/guided-start.md`。
- 角色、受体或正式度影响表达时读取 `references/audience-and-role.md`。
- 涉及对抗、刑事指控、监管、多法域、敏感信息或现行样式时读取 `references/context-modifiers.md`。
- 两份以上关联材料或用户要求前后核对时读取 `references/multi-document-review.md`。
- 现场发言、辩护、代理、公诉或宣读材料时读取 `references/oral-expression.md`。
- 近义法律术语、身份称谓或法律效果词时读取 `references/terminology-map.md`。

不要在普通任务中读取索引文件。只有追溯规则依据或核对来源状态时，才读取 `references/rule-index.md`、`references/source-index.md` 和 `references/legacy-rules-r001-r045.md`。

### 状态 5：执行处理

#### 四种转换模式

- **轻度润色**：修正语病、冗余、指代和格式，不重构成熟文本。
- **专业改写**：规范术语、调整句式和组织逻辑，作为一般默认。
- **严格审校**：检查语义、结构、风险、引用和一致性，适用于合同、诉讼仲裁、法律意见、律师函和高风险外发文本。
- **通俗转译**：向非法律读者解释必要术语，保持结论强度和例外。

#### 两个专项动作

- **结构诊断**：只报告工作产品、受体、主命题、信息层级、对应关系和缺口；除非用户同时要求，不提供改写稿。
- **文书链核对**：比较多份文本中的主体、角色、日期、金额、术语、请求、证据状态、立场、引用和结果；除非用户同时要求，不统一改写全部文件。

用户已明确处理动作时直接采用。未指定时，普通文本默认建议专业改写；高风险文本建议严格审校。

### 状态 6：完成双重复核

严格审校、结构诊断、文书链核对、长文本及高风险文本必须读取 `references/quality-checklist.md`。

1. **校异同**：对照原文、附件、引文及关联文书检查语义与数据。
2. **校是非**：检查本稿内部的主体、术语、条件、逻辑、结构和表达。

发现疑似实体法律错误时只标记“需核验”，不得静默修正。

### 状态 7：交付

- 轻度润色或专业改写：`修改稿`；必要时增加 `需确认事项`。
- 严格审校：`修改稿`、`需确认事项`、`主要修改`。
- 通俗转译：`修改稿`；必要时增加 `术语说明`。
- 结构诊断：`路由判断`、`结构诊断`、`信息缺口与风险`、`建议处理顺序`。
- 文书链核对：`核对范围`、`一致事项`、`差异与风险`、`建议修正`。
- 用户同时要求专项动作与改写时，先报告诊断或差异，再提供修改稿。

保留原有编号、标题层级和引用格式，除非用户明确要求重构。

## 多领域与交叉领域处理

- 先按工作产品和沟通关系路由，不要求用户选择部门法。
- 一项事务涉及多个领域时，不加载多套部门法模块；只增加必要的语境修正。
- 涉及不同法域、现行规范或实体判断时，明确标记核验边界，并建议结合相应法律研究 Skill。
- 同一材料包含多种工作产品时，以最终希望读者采取的行动确定主类型。
