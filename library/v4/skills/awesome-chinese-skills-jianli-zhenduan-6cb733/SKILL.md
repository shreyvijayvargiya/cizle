# 简历诊断与重写

## 核心原则

简历的唯一目标是拿到面试，不是记录人生。判断一切改动的标准：目标岗位的筛选者（HR 或 ATS 系统）在 30 秒内能否看到"这个人干过我要的事"。

## 执行流程

```
诊断进度：
- [ ] 第 1 步：收集简历与目标岗位
- [ ] 第 2 步：结构扫描
- [ ] 第 3 步：逐条量化改写
- [ ] 第 4 步：关键词对齐
- [ ] 第 5 步：输出诊断报告 + 新版简历
```

### 第 1 步：收集材料

必须向用户拿到：
- 简历全文（粘贴或文件）
- 目标岗位 JD 原文（1-3 个）
- 用户能补充的真实数据（没有量化数字的经历，提问挖："大概多少人参与？提升了多少？省了多少钱？"）

### 第 2 步：结构扫描

检查并记录问题：
- 篇幅：应届 ≤ 1 页，10 年内 ≤ 2 页，超出即删次要内容
- 顺序：最近经历在前；与目标岗最相关的经历放最显眼位置
- 废信息：证件照声明、"本人性格开朗"式自评、与岗位无关的早期兼职
- 时间断点：超过 6 个月的空窗，提前准备一句话解释（不写进简历）

### 第 3 步：逐条量化改写

每段经历改写为：**动词开头 + 做了什么 + 方法/工具 + 可量化结果**。

改写前：「负责公众号运营」
改写后：「独立运营公众号，10 个月产出 84 篇文章，粉丝从 0 做到 2.3 万，单篇最高转化 400+ 订单」

规则：
- 消灭"负责、参与、协助"开头的职责式描述，改为成果式
- 每条经历 1-3 个 bullet，每 bullet ≤ 35 字
- 用户给不出数字的经历，标注【待补数据】，不许编造

### 第 4 步：关键词对齐

从每个 JD 提取 8-12 个硬关键词（技能、工具、领域、资质），逐一检查简历是否出现；缺失但用户真实具备的，补进对应经历或技能栏；用户不具备的，明确告知不要写。

### 第 5 步：输出

交付两部分：
1. **诊断报告**：问题清单（结构/量化/匹配三类），每条注明位置和改法
2. **新版简历全文**：ATS 友好格式（纯文本结构，不用表格和多栏）

## 红线

绝不虚构经历、公司、时间、数据。宁可留【待补数据】占位并向用户提问。
